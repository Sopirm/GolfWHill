Практическая работа

Программирование создания и физического моделирования объектов 

Цель работы - освоить работу с системой ввода Unity (Input System Package) для обработки пользовательского ввода. Научиться динамически создавать и уничтожать игровые объекты во время выполнения программы. Изучить применение триггерных коллайдеров для обработки пересечений и освоить технологию рейкастинга (Physics.Raycast) для обнаружения объектов в игровом мире.

Теоретические сведения

В Unity 6 для обработки пользовательского ввода доступны два подхода: устаревший Input Manager и более современная система Input System Package (рис. 1). В актуальной практике рекомендуется использовать именно Input System, так как она лучше поддерживается, позволяет абстрагировать игровые действия от конкретных устройств ввода и удобнее масштабируется при работе с клавиатурой, мышью, геймпадом и другими источниками ввода. Вместо прямой привязки к клавишам разработчик описывает действия игрока, например Move, Look, Jump, Spawn, а затем назначает им нужные элементы управления. 

Рисунок 1. Input System Package
Ключевым понятием новой системы являются Input Actions (рис. 2). Они разделяют логический смысл действия и физическое устройство, которое это действие вызывает. Благодаря этому один и тот же игровой сценарий можно запускать нажатием клавиши на клавиатуре, кнопки на геймпаде или другим управляющим сигналом без переписывания основной логики. Для работы с такими действиями можно использовать как прямое обращение к сгенерированному C#-классу, так и компонент PlayerInput (рис. 3), который автоматически управляет включением и выключением действий и может вызывать публичные методы компонентов объекта. 

Рисунок 2. Input Actions Editor

Рисунок 3. Компонент Player Input
Во время работы приложения Unity позволяет создавать и удалять объекты программно. Для этого применяется метод Instantiate, который создает новый экземпляр объекта, чаще всего — на основе заранее подготовленного префаба. Такой подход используется для спавна снарядов, подбираемых предметов, врагов, визуальных эффектов и временных игровых сущностей. Если объект должен быть удалён, применяется метод Destroy. В современной структуре проекта префаб выступает шаблоном, содержащим геометрию, компоненты, материалы и настройки поведения будущего объекта. 
Для регистрации зон взаимодействия в Unity используются триггеры. Триггер — это коллайдер с включённым параметром Is Trigger (рис. 4). В отличие от обычного столкновения, он не создает физического отталкивания, а лишь сообщает системе, что один объект вошёл в область другого, находится внутри неё или покинул её. Для этого применяются методы OnTriggerEnter, OnTriggerStay и OnTriggerExit. Unity вызывает эти методы при пересечении коллайдеров, если соблюдены условия физической системы; как правило, один из взаимодействующих объектов должен участвовать в физической симуляции через Rigidbody. События триггеров относятся к физическому циклу и фиксируются в логике физического шага. 

Рисунок 4. Параметр Is Trigger компонента Collider
Система Physics.Raycast используется для посылки луча в пространстве сцены и проверки, пересекает ли он какой-либо коллайдер. Это один из базовых инструментов игровой логики: с его помощью определяют объект перед камерой, реализуют стрельбу, взаимодействие с предметами, проверку видимости, обнаружение поверхности под персонажем и многие другие механики. Если луч попадает в объект, Unity может вернуть структуру RaycastHit, содержащую сведения о точке попадания, расстоянии, нормали поверхности и самом объекте. Отдельно важно учитывать, что поведение лучей по отношению к триггерам может зависеть как от параметров конкретного вызова, так и от глобальных настроек Physics, где существует опция обработки триггеров в физических запросах. 
Таким образом, Input System отвечает за получение намерений пользователя, Instantiate — за создание игровых сущностей, триггеры — за регистрацию входа в области взаимодействия, а Physics.Raycast — за направленную проверку пространства. В совокупности эти инструменты образуют основу интерактивного поведения в большинстве трехмерных проектов на Unity.

5. Создание скрипта для спавна объекта через новую систему ввода
Создайте C#-скрипт ObjectSpawner и поместите в него следующий код:
Листинг 1
using UnityEngine;
using UnityEngine.InputSystem;

public class ObjectSpawner : MonoBehaviour
{
    public GameObject prefabToSpawn;
    public Transform spawnPoint;
    public float spawnForce = 5f;

    private InputSystem_Actions inputActions;
    private bool spawnRequested;

    void Awake()
    {
        inputActions = new InputSystem_Actions();
        inputActions.Player.SpawnObject.performed += ctx => spawnRequested = true;
    }

    void OnEnable()
    {
        inputActions.Enable();
    }

    void OnDisable()
    {
        inputActions.Disable();
    }

    void Update()
    {
        if (spawnRequested)
        {
            spawnRequested = false;

            if (prefabToSpawn == null || spawnPoint == null)
                return;

            GameObject spawnedObject = Instantiate(
                prefabToSpawn,
                spawnPoint.position,
                spawnPoint.rotation
            );

            Rigidbody rb = spawnedObject.GetComponent<Rigidbody>();
            if (rb != null)
            {
                rb.AddForce(spawnPoint.forward * spawnForce, ForceMode.Impulse);
            }
        }
    }
}

В данном случае используется тот же подход, что и в 6-й: скрипт получает экземпляр InputSystem_Actions, подписывается на событие действия в Awake(), включает действия в OnEnable() и выключает в OnDisable(). Вместо прямой проверки клавиш логика работает через событие из action map Player, что сохраняет единый стиль проекта

using UnityEngine;

public class TriggerZoneHandler : MonoBehaviour
{

Добавьте этот скрипт на объект TriggerZone.

8. Создание скрипта взаимодействия через Physics RayCast
Создайте C#-скрипт RaycastInteractor:
Листинг 3
using UnityEngine;
using UnityEngine.InputSystem;

public class RaycastInteractor : MonoBehaviour
{
    public Camera playerCamera;
    public float rayDistance = 10f;

    private InputSystem_Actions inputActions;
    private bool interactRequested;

    void Awake()
    {
        inputActions = new InputSystem_Actions();
        inputActions.Player.RaycastInteract.performed += ctx => interactRequested = true;
    }

    void OnEnable()
    {
        inputActions.Enable();
    }

    void OnDisable()
    {
        inputActions.Disable();
    }

    void Update()
    {
        if (!interactRequested)
            return;

        interactRequested = false;

        if (playerCamera == null)
            return;

        Ray ray = new Ray(playerCamera.transform.position, playerCamera.transform.forward);
        RaycastHit hit;

        if (Physics.Raycast(ray, out hit, rayDistance))
        {
            Debug.Log("Луч попал в объект: " + hit.collider.name);
            Debug.Log("Точка попадания: " + hit.point);
            Debug.Log("Расстояние: " + hit.distance);
        }
        else
        {
            Debug.Log("Объект не найден");
        }
    }
}

Этот скрипт построен по той же схеме, что и предыдущие скрипты с Input System: через экземпляр InputSystem_Actions, подписку на действие и дальнейшую обработку запроса в ходе работы сцены.
9. Подключение RayCast-скрипта
Добавьте скрипт RaycastInteractor на объект игрока. В поле Player Camera перетащите основную камеру, которая уже используется персонажем. В поле Ray Distance установите, например, значение 10.
Разместите перед игроком несколько объектов с коллайдерами: стены, кубы, физические предметы, созданные вручную или через спавн. Запустите сцену и нажмите клавишу, назначенную действию RaycastInteract. Если луч попадает в объект, в Console должна появиться информация о попадании (рис. 12).
